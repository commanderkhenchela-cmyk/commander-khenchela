# لوحة تحكم الإدارة — Commander Khenchela

تطبيق Next.js (TypeScript) يسمح لفريق الإدارة بـ:

- الموافقة على/رفض طلبات انضمام المحلات
- إدارة تصنيفات المنتجات
- متابعة كل الطلبات، تحديد رسوم التوصيل لكل طلب، وتحديث حالته ضمن
  الصلاحيات المسموحة للإدارة فقط (الاستلام من المحل، الانطلاق للعميل،
  التسليم، الإلغاء) — أي شيء آخر (موافقة/تجهيز التاجر) من صلاحية التاجر
  فقط، ويُمنع من طرف قاعدة البيانات (trigger) حتى لو حاول الأدمين تجاوزه
- تعديل نسبة عمولة المنصة

## ⚠️ لا توجد صفحة "إنشاء حساب" هنا — عمدًا

حسابات الإدارة **لا تُنشأ ذاتيًا** من أي تطبيق (خطر أمني إذا سُمح بذلك).
لإنشاء أول حساب إدارة:

1. **Supabase Dashboard → Authentication → Users → Add user**
   أضف بريدًا إلكترونيًا وكلمة مرور.
2. في نفس الشاشة، أضف في **User Metadata** (JSON):
   ```json
   { "role": "admin", "full_name": "اسمك" }
   ```
3. Trigger موجود مسبقًا في قاعدة البيانات (`handle_new_user`) سينشئ
   تلقائيًا صفًا في `public.users` بـ `role = 'admin'` لهذا الحساب.
4. سجّل الدخول بهذا الحساب من هذا التطبيق مباشرة.

## التشغيل محليًا

```bash
npm install
cp .env.local.example .env.local   # ثم ضع القيم الحقيقية
npm run dev
```

افتح http://localhost:3000

## الأمان

- لا يُستخدم أي مفتاح سري (`service_role`) في هذا التطبيق إطلاقًا — فقط
  `publishable key` العام، عبر متغيرات البيئة (`.env.local`، غير مرفوع
  لـ GitHub).
- كل صلاحية إدارية (الموافقة على محل، تغيير حالة طلب، تعديل الإعدادات)
  محمية بشرط `role = 'admin'` إما داخل RLS Policy مباشرة أو داخل دالة
  Postgres بصلاحية `security definer` تتحقق من الدور بنفسها قبل أي تنفيذ
  (راجع `supabase/migrations/20260820030000_admin_capabilities.sql`).
